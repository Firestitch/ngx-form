A dialog with side tabs, top tabs inside them, a form scoped to just the Settings tab's fields, an instant-save panel beside it, and Save/Cancel in the dialog footer outside every form.

The dialog carries fsFormContainer rather than a form of its own - no ngForm, no wrapper element, no empty control namespace. Forms register into it as tabs mount, the footer buttons resolve to it, and <fs-form-dialog-actions> is left completely bare.

  • Edit a Settings field → Save enables. Edit the Status panel → it doesn't.
  • Save validates only the mounted tab's fields, never the whole dialog.
  • Switch Settings ↔ Notes and Save keeps working - it follows the mounted form.
  • Go to Activity, which has no form, and the footer shows Done on its own.
  • Close with unsaved Settings edits and it prompts; with only panel edits it doesn't.
